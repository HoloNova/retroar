# RetroAR：文献核验与下一轮实验建议

> 本文记录首轮长实验之后的文献核验。它不是完整的系统综述，也不等于已完成与全部前期工作的对照审计。文献中的实验结果主要来自作者自己的预印本，不能直接当作独立复现结果。

## 1. 先给结论

**“让自回归模型生成时能够修改前文”不是空白赛道。**至少以下几条路线已经覆盖了宽泛的“可修订生成”：

- 对已生成的 hard token 进行窗口内重采样；
- 通过特殊动作 token 回退并编辑历史；
- 对块内 token 做前向预测和后向重建；
- 在连续向量空间中延迟离散提交，并维护可变后缀；
- 更早的非自回归迭代重写、插入/删除和 mask 重预测。

其中，**Projected Autoregression（PAR，arXiv:2601.04854）是目前发现的最接近者**：它明确提出 continuous prediction、delayed commitment 和短的 mutable “liquid tail”，而且仍保持左到右的因果生成。RetroAR 不能再把“延迟提交＋可修改后缀”本身当作与前人不同的地方。

当前仍可能形成研究问题，但表述应收窄为：

> 在严格的左到右增长过程中，使用离散词表上的 categorical soft belief，并让未提交位置随新一轮计算自动更新；这种状态表示与提交规则，是否在需要后续证据的任务上比 hard revision、token resampling 或连续向量 tail 更合适？

这句话是**待检验的问题**，不是已经确认的机制优势。

## 2. 核验到的最接近工作

| 工作 | 它实际做了什么 | 与当前想法的重叠 | 仍有的区别 |
|---|---|---|---|
| [Mask-Predict](https://aclanthology.org/D19-1633/)（2019） | 固定长度序列，反复 mask 低置信度位置并重新生成 | 证明全局迭代修订很早已有成熟路线 | 不是左到右增长，也不是未提交前缀的在线状态 |
| [Levenshtein Transformer](https://proceedings.neurips.cc/paper_files/paper/2019/hash/675f9820626f5bc0afb47b57890b466e-Abstract.html)（2019） | 通过删除、插入反复修改序列，长度也可以变化 | 证明离散序列编辑不是新问题 | 没有 categorical soft belief 的连续更新 |
| [COrAL](https://arxiv.org/abs/2410.09675)（2024） | 在滑动块中进行多 token 前向预测和后向重建，利用 order-agnostic 结构做迭代细化 | 已把“生成中向后修订”放进模型内部 | 它是块级、非严格单调的 order-agnostic refinement，不是当前设想的 soft prefix＋commit 边界 |
| [Corrector Sampling / RPT](https://arxiv.org/abs/2506.06215)（2025） | 训练 next-token 与 previous-token 条件，在固定窗口中重采样之前生成的 hard token | 与“后面的 token 帮前面纠错”非常接近；是当前 hard baseline 的重要前人 | 更新的是离散 token，需要额外的 previous-token 条件；不是 soft 概率状态 |
| [Projected Autoregression](https://arxiv.org/abs/2601.04854)（v3） | 预测连续 token embedding，维护可变的 liquid tail，成熟后再 nearest-neighbor 投影成离散 token | **最直接重叠：左到右、延迟提交、短可变后缀、局部 refinement** | 它的状态是连续 embedding vector，当前实验是 3 类 categorical probability；它主要修订短后缀，当前 PoC 在最终定稿前让全部位置可变 |
| [Stream of Revision](https://arxiv.org/abs/2602.01187)（v2） | 增加 backtracking、OLD/NEW 等动作 token，用 renderer 对 hard history 做原地 patch | 覆盖“单次 AR 流中进行修订” | 是显式 hard edit action，目标是安全代码；不是自动演化的 soft belief |
| [COCONUT](https://arxiv.org/abs/2412.06769)（2024） | 把连续 hidden state 作为后续 thought 的输入，研究连续思考和回溯 | 说明连续内部状态反馈与 backtracking 早有研究 | 重点不是输出 token 的未提交/提交机制 |

### 对几篇最关键文献的核对

- **COrAL 的摘要**明确说它在 context window 中做 multi-token forward prediction 和 backward reconstruction，并进行 sliding blockwise iterative refinement；它不是普通 AR 的简单“再算一次”。
- **Corrector Sampling 的摘要和方法**明确说 RPT 会在过去 token 的窗口中迭代替换 token，并学习给定未来 token 的 previous-token conditional。这比当前 `hard` 模式更具体，也说明“未来位置帮助前面 hard token”已有直接先例。
- **PAR 的摘要和方法**明确写出 `continuous prediction → discrete projection at commitment time`，以及可选的 mutable suffix/liquid tail；它还说明 refinement 是 local short causal suffix，而不是全局 diffusion。
- **Stream of Revision**明确把 revision 表达为 augmented vocabulary 中的动作 token，再由 renderer 把操作流编译成最终程序。它不是 soft state，但已经否定“AR 中原生修订从未有人做过”的说法。

## 3. 对当前 RetroAR 实现的审计

首轮实现有价值，但它验证的命题比原始构想窄，也不同于严格的在线 RetroAR。

### 3.1 它确实验证了什么

`results/long_v1/report.md` 的 15 次固定实验显示，在当前三色唯一解图任务上：

- 普通生成：77.47% ± 4.66% 整题准确率；
- 确定草稿回改：85.03% ± 0.98%；
- 概率草稿回改：87.37% ± 3.25%；
- 多算一次但不改历史：74.09% ± 1.76%；
- 概率反馈但不回改：75.78% ± 5.91%。

因此可以谨慎地说：

> 在这个小型任务和当前训练设置下，让离散草稿状态参与后续预测并重新计算已出现位置，出现了比不回改更好的信号。

这是“值得继续”的可行性证据。回改版本每题使用两倍主要网络调用，不能称为免费提升；概率回改相对确定回改的平均优势为 2.34 个百分点，但逐种子差异是 +0.39、−0.39、+7.03 个百分点，不能称为稳定优势。

### 3.2 三个关键混杂因素

1. **没有真正的 delayed evidence。**
   `retroar_min/model.py` 的 `rollout` 文档明确写着完整图输入始终可见；模型从第一步就看到完整邻接矩阵。后续位置没有带来外部新事实。因此当前实验不是“后来出现的新信息纠正前文”，而是“模型在完整约束已知时进行迭代式自我修订”。

2. **模型不是严格的 causal AR。**
   `ColorModel.forward` 把完整 `adj` 输入 Transformer encoder。所谓从左到右，只限制 proposal 的读取和反馈顺序；网络本身通过 full self-attention 处理所有图位置。它更接近“在固定全局条件上逐步更新状态”的小型迭代推断。

3. **没有 commit window。**
   当前实验直到最后才统一定稿，之前所有位置都可以变化。原始构想中最重要的“左侧已经提交、窗口内仍可修订、达到条件后提交”尚未实现。因此不能用首轮结果证明流式输出或有限窗口的优势。

还有一个公平性边界：`extra_compute` 让模型做了相同数量的主要前向和额外监督，但它不是“完整生成后再优化”的唯一合理基线。仍需加入 post-hoc full refinement、计算预算匹配的 AR 和更严格的时间/调用量比较。

## 4. 下一轮最小实验：先修正因果与提交问题

不建议立即训练语言模型。下一轮应分成两个很小的阶段。

### 阶段 A：把现有图任务的结论做干净

目的不是扩大模型，而是知道首轮提升到底来自哪里。新增三个对照：

1. **Post-hoc refinement**：先用普通方式生成整段，再用相同次数的 full refinement 修改整段；用于比较“在线边生成边改”与“写完再改”。
2. **严格计算匹配 AR**：让普通 AR 获得相近的前向次数、训练时间或 optimizer update budget；不能只让 revision 版本多算。
3. **无 soft mixture 的等输入消融**：保持修订结构不变，但把历史分布压成 argmax 或受控温度分布，分离“回改”和“保留概率”的影响。

同时记录：

- 每个位置第一次预测与最终预测的准确率；
- 错改对、对改错的比例，而不是只看最终整题；
- 每一轮熵、分布变化量和振荡次数；
- 每次前向、每个样本的实际墙钟时间；
- 模型是否在训练后把 soft 分布迅速变成接近 one-hot。

阶段 A 的解释边界：即使回改仍然更好，也只能说明“小型全局约束上的迭代修订有用”。

### 阶段 B：用真正的 delayed-evidence 任务检验核心假设

构造一个很小的流式约束任务：

1. 每个样本有一组二值变量和若干 XOR/parity、噪声观察或唯一性约束；完整约束保证有唯一答案。
2. 约束不是一次性给模型，而是按时间逐条揭示。
3. 模型每轮先根据当前已揭示信息提出下一个答案，同时维护最近 `K=3` 个尚未提交位置。
4. 新约束到达后，hard 版本只能保留/替换窗口中的确定值，soft 版本保留每个位置的二值概率并重新更新窗口。
5. 窗口左端达到年龄或稳定条件后才 commit；最后再 flush 剩余窗口。

最小对照：

- 标准 causal AR：每个位置立即 commit；
- hard rollback：窗口内保留确定值并允许重写；
- soft revision：窗口内保留概率；
- full-information upper bound：一开始看到全部约束，只用于测任务上限，不作为公平在线基线。

主要指标：最终完整答案准确率、每轮提交延迟、错改对/对改错、窗口振荡、每题前向次数和墙钟时间。只有 soft 在计算相近时稳定优于 hard，才有理由继续声称“soft belief”有独特价值。

这个任务测试的是**外部延迟信息**。它不把模型自己生成的后文冒充为独立证据。若要研究“模型自己的后文是否能帮助修订”，应另设一组完整约束已知的 self-consistency 任务，并明确把它称为迭代推断，而不是 future evidence。

## 5. 阶段门与停止标准

下一轮不自动扩大到大模型。建议：

- 阶段 A 若 post-hoc refinement 与在线 revision 一样好，在线机制的独特性暂时不成立；
- 阶段 B 若 soft 不稳定优于 hard，研究焦点应转为“什么时候 hard revision 已足够”，而不是坚持 soft；
- 若收益只出现在 full-information 图任务，不能宣称解决了 AR 的未来信息问题；
- 若 soft 在 delayed-evidence 任务上稳定优于 hard、计算代价可解释，再考虑把 categorical state、commit gate 和窗口机制实现成正式算法；
- 只有在合成任务上有稳定机制结果后，才进入小型代码/结构化文本任务。

## 6. 当前可用的表述边界

暂时不能使用：

- “首次让自回归模型修改历史”；
- “首次提出延迟提交或可变后缀”；
- “没有类似工作”；
- “人类会回改，所以模型这样一定更强”。

如果后续阶段成立，较稳妥的定位是：

> 我们研究一种离散 soft-belief 的有限在线修订机制，并通过延迟证据任务分析 categorical belief、hard rollback、连续状态 tail 与计算预算之间的关系。

这个表述把主张从宽泛口号转成一个可以被前人方法击败、也可以被实验否证的问题。

## 7. 目前决定

文献核验已完成到“最接近工作的初筛”层级，结论已写入本文。首轮长实验结果已经保存，不追加训练、不修改旧结果。下一步若继续实现，应先做阶段 A 的三个对照，并在代码中明确区分：

- `online_revision`；
- `posthoc_refinement`；
- `streaming_delayed_evidence`。

在这些对照完成前，不建议提出机制优势声明或扩大模型规模。


## 8. 阶段 A 已完成：新的决策

阶段 A 的 40 次运行全部完成，完整报告见 `results/stage_a_v1/report.md`。结果如下：

- `posthoc_soft` 为 92.50% ± 1.15%，`soft` 为 88.05% ± 2.50%；写完后再修订平均高 4.45 个百分点，5 个种子全部更高。
- `posthoc_hard` 为 88.28% ± 1.27%，`hard` 为 84.53% ± 1.19%；写完后再修订平均高 3.75 个百分点，5 个种子全部更高。
- `ar_matched` 为 77.34%，普通 `ar` 为 76.95%；纯增加相同前向计算没有稳定收益。
- `soft` 比 `hard` 平均高 3.52 个百分点，但种子差异仍明显。

因此，当前最重要的结论是：**在这个完整图条件已知的任务上，迭代修订有效，但在线修订没有优于 post-hoc 全序列修订。**这削弱了“在线边生成边回改”具有独特优势的证据，增强了“全局/后验 refinement 有用”的解释。

还不能把 post-hoc 优势完全归因于修订顺序：post-hoc 每一轮都监督完整序列，在线版本只监督当前前缀；虽然主要 forward call 数量匹配，但有效监督量不匹配。下一步如要继续，应先修正这一点，或直接转向更能区分两者的 streaming delayed-evidence 任务。

当前研究决策：不扩大模型、不提出机制优势声明；优先实现二值/小词表的流式延迟证据任务，比较立即提交、hard window 和 soft window。
