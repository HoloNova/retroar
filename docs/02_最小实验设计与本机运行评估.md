> 状态：首版已实现并通过 15 项测试；首轮长实验的 15 次训练全部完成。本文保留历次评估；实现记录见第 10 节，最新结果与解释见第 11 节。
> 上游材料：`01_研究构想与交接说明.md`。本文件不覆盖原文；当前最小实验以本文的简化范围为准。

## 1. 研究目标与定位

本项目首先是把一个直觉收敛成可检验的问题，不是立即开发实用大模型产品。

核心直觉：模型每向后生成一个位置，都重新调整前面尚未定稿的草稿，类似人说话前在脑中修改表达。

需要回答两个问题：

1. 边生成边回改，是否能改善最终答案？
2. 保留多个候选的概率，是否比只保留一个确定候选再回改更有用？

人类构思的类比只用于说明动机，不是方法有效的证据。当时尚未核验相关前期工作，不能宣称首创或已占据无人研究的方向。

负面结果同样有记录价值，但必须揭示可靠、可解释的失败规律；单次训练不成功不等于方向无效。

## 2. 与原始方案相比的简化

第一版只实现：生成模块、修改模块、一段保存候选概率的草稿。

- 每生成一个位置，修改一轮所有已出现的位置，包括最新位置。
- 全部生成完后，统一选择每个位置概率最高的候选作为答案。
- 暂不做滑动窗口、逐步提交、学习式门控、缓存优化或真实语言模型。
- 暂不追求流式输出。因此第一版只检验生成与修订机制，不能证明原始方案中的在线提交或延迟优势。

所有题目条件从一开始就对模型可见。后续草稿由模型自己生成，不逐步提供真实答案作为“未来证据”。自己生成的后文不是独立事实，但更多计算可能帮助发现已有选择的矛盾，也可能强化错误。

## 3. 最小任务：三色填图

给定一张小图：

- 每个点只能填红、绿、蓝中的一种。
- 有连线的两个点不能同色。
- 部分点的颜色已指定。
- 模型按预定顺序输出其余点的颜色；一个颜色相当于一个 token。

先从每题 6～8 个待填位置开始，题目条件始终完整可见。此任务容易自动检查答案，不需要下载自然语言数据。

用普通求解程序生成和检查题目。第一轮优先使用指定部分颜色后只有一个合法解的题，以便清楚判断修改是从错到对还是从对到错。求解程序不在模型作答时提供提示。

数据先按原始题目划分训练集和测试集，再进行节点重排等增强，防止同一题换编号后进入测试集。具体生成规则、去重和难度分布在实现阶段确定并记录。唯一解题目的选择可能带来分布偏差，后续需要检查。

限制：这是人为设计的小型约束任务，成功不代表能改善自然语言生成。题目条件一开始就完整给出，也不保证必须依靠后续生成才能求解；普通模型同样可以从完整输入中求解，这是公平对比的一部分。

## 4. 模型与程序流程

### 4.1 草稿表示

每个位置保存三个数字，分别是红、绿、蓝的概率。例如：

```text
位置1：红 0.6，绿 0.3，蓝 0.1
位置2：红 0.2，绿 0.7，蓝 0.1
```

把三种颜色的向量按概率加权，作为后续模块的输入。这种混合表示不等于同时保存所有完整候选解；是否会混淆不同假设，是需要观察的风险。

### 4.2 两个模块

- 生成模块：读取题目和已有草稿，输出下一个位置的三个概率。
- 修改模块：读取题目和当前全部草稿，输出修订后的概率表。

计划用 PyTorch 的小型 Transformer 组件实现，初始目标为几万到十几万参数，实际参数量在实现后统计。不下载预训练大模型。

```python
草稿 = []
for 每个待生成的位置:
    新候选 = 生成模块(题目, 草稿)
    草稿.append(新候选)
    草稿 = 修改模块(题目, 草稿)
答案 = 对每个位置选择概率最高的颜色(草稿)
```

这是说明流程的伪代码，不是可直接运行的实验脚本。

### 4.3 训练

使用正确答案计算训练误差，并更新网络参数。关键的连续生成训练与测试中，后续位置来自模型自己的草稿，不输入正确后文帮助回改。

可先让模型学会少量题目，验证数据、误差计算和训练链路，再检查完整的自主生成与修订流程。各版本采用尽量一致的训练规则。

实现前还需明确：修订前后误差如何加权、是否让梯度跨多个生成步骤传播，以及确定候选与概率候选的反馈如何公平比较。这些属于待落实的实现细节，不能把训练路径的差异误认为软状态的收益。

## 5. 对照实验

第一轮运行三个版本：

| 版本 | 行为 | 用途 |
|---|---|---|
| A：不回改 | 选定颜色后不再修改 | 基础参照 |
| B：确定草稿回改 | 每个位置反馈一个确定颜色，允许后续修改 | 检查回改本身 |
| C：概率草稿回改 | 反馈候选概率，允许后续修改 | 检查软候选的额外作用 |

B 与 C 尽量保持相同模块规模、修订次数、输入信息和训练设置。记录实际差异，不能声称天然严格公平。

出现初步信号后再补：

- 相同计算预算下，多做内部计算但不回改的对照。
- 相近计算预算下，全部生成完再统一修改的对照。
- 必要的无修订软反馈消融，以区分软反馈与回改的作用。

第一轮即使 C 优于 A，也不能直接证明软修订优于更多计算或更晚定稿。

## 6. 评价与继续条件

记录：

- 整题成功率：是否满足所有条件。
- 修改效果：错改对、对改错的次数及净变化；统计时用各轮概率最大的颜色判断。
- 计算代价：训练和推理耗时、资源使用、模型参数量、修订次数。
- 过程样例：每一步各位置的概率与最终选择。

先用一次短跑排查实现，不将其作为研究结论。有信号后至少用三个随机种子重复，再增加任务规模和更严格的计算匹配。

判断原则：

- C 稳定优于 B：值得继续检查软候选的独特价值。
- B 与 C 相近且都优于 A：可能主要是回改有用。
- 同预算普通方法追平：不能归因于修订机制。
- 写完再改更好：在线回改的必要性需要重新评估。
- 所有方法接近全对或都学不会：先调整任务难度或排查训练，不直接得出机制结论。

首轮交付：一个对比表、若干修改轨迹、明确的继续/调整/停止建议。不承诺正面结果。

### 9.4 数据与训练的有界运行

分开设置两个档位：

1. **冒烟检查**：用约 16 道题检查合法性、张量形状、一次前向和反向更新，以及能否开始拟合少量训练题。它不是效果评估。
2. **短跑比较**：目标 256 道训练题、64 道独立测试题；每个版本最多 200 个训练更新，训练与评估合计最多 120 秒，先到哪个上限就停。A、B、C 依次运行，不并发。停止原因、实际更新数和处理题数必须记录，不能把不同完成度当作公平训练的结论。

数据生成单独设置 60 秒和 10,000 次候选尝试上限。6 个待填点至多有 3^6=729 种配色，可用小型回溯求解器计数，发现两个解即可停止唯一性检查。若无法在上限内凑足独立唯一解题目，报告数据不足并调整生成策略，不无限拒绝采样、不偷偷重复题目凑数。

256/64 是试跑目标，不是正式实验的数据规模。只有确认运行正常且有可解释现象，才扩大到 8 个位置、更多数据或多个随机种子。

### 9.5 内存与时间保护

- 启动实验前，可用内存低于 1.5 GiB 则拒绝开始。
- 每个版本使用独立子进程，结束后释放其内存，再启动下一个版本。
- 外层监控约每秒检查一次本实验子进程的常驻内存与全机可用内存。
- 若实验子进程常驻内存超过 1.0 GiB，或全机可用内存低于 768 MiB，则停止本实验并报告，不影响其他进程。
- 外层对导入/初始化设置独立的 60 秒启动上限；短跑阶段执行上述 120 秒上限。依赖下载安装不计入训练限时，需独立说明。
- 这些是保守的操作阈值，不是内存占用预测；轮询保护也不能保证捕捉所有瞬时内存峰值。若 PyTorch 基础运行时就触及阈值，先报告，不自动提高阈值。
- 不使用虚拟地址空间限制冒充物理内存限制；不创建无限训练循环，不保留所有步骤的计算图和大批日志。
- 每个批次按既定训练图完成反向更新后释放计算图，轨迹日志只保存少量样例的普通数值。不得为了省内存，暗中改变软/硬版本的梯度规则；该差异需在实现前明确并记录。

## 11. 首轮长实验已完成：结果与解释

15 次训练全部完成 5000 步，没有触发时间预算停止。逐项核验数据/源码指纹、模式与种子完整性、256 道测试题数量及约束成功率，均通过。各训练进程记录的总耗时约 50.39 分钟，不含调度与启动开销，峰值内存低于 293 MiB。

正式测试集整题准确率，均值 ± 三个种子的标准差：

| 方法 | 整题准确率 |
|---|---:|
| 普通生成 | 77.47% ± 4.66 个百分点 |
| 多算一次、不改历史 | 74.09% ± 1.76 个百分点 |
| 确定草稿回改 | 85.03% ± 0.98 个百分点 |
| 概率草稿回改 | 87.37% ± 3.25 个百分点 |
| 概率反馈、不回改 | 75.78% ± 5.91 个百分点 |

### 支持什么

在这一小图任务、当前模型与训练设置中，回改版本表现出积极信号。概率回改相对普通生成平均高约 9.90 个百分点，但主要网络调用次数也翻倍，不能直接声称同计算预算优势。相对同调用次数的“不改历史、多算一次”对照，确定与概率回改均表现更好，提示收益不只是来自本实验这种额外计算方式。

### 尚不能支持什么

概率回改比确定回改的平均提升约 2.34 个百分点，但逐种子差异为 +0.39、-0.39、+7.03 个百分点，平均优势主要来自一个种子。尚不能断言软候选稳定优于确定候选，也未做统计显著性证明。

普通生成对照本身还可以进一步加强，例如同训练计算预算延长训练、整段生成后精修。三次随机初始化共享同一数据划分，不能代替多个独立数据集。首次结果不支持自然语言泛化或普遍性结论。

### 当前决定与下一步建议

当前结论是“边生成边回改值得继续研究”，不是“概率草稿机制已被证明”。下一步优先建议核验关键相关文献，并设计更严格的软/硬候选比较及写完再改对照。先向用户解释本次结果，再确认下一轮范围，不自动追加训练。

完整报告：`results/long_v1/report.md`；逐种子指标、检查点和修改轨迹保存在对应子目录。预先固定的 `03_协议_首轮长实验.md` 保持原样，作为实验前约定的记录。文献核验、当前实现的因果混杂审计和下一轮建议见 `04_文献核验.md`。

## 13. 阶段 A 完成结果

阶段 A 的 40 次训练已完成，结果保存在 `results/stage_a_v1/`。5 个种子、8 个模式均完成 5000 步，数据和源码指纹核验通过，峰值内存不超过 293.5 MiB。

`posthoc_soft` 为 92.50% ± 1.15%，`soft` 为 88.05% ± 2.50%；`posthoc_hard` 为 88.28% ± 1.27%，`hard` 为 84.53% ± 1.19%。这说明当前任务上的迭代修订有效，但写完后再统一修订比在线边生成边修订更强。`ar_matched` 与普通 `ar` 仅相差 0.39 个百分点，纯额外计算没有稳定收益。

解释仍受监督数量差异影响：post-hoc 每轮监督完整序列，在线版本只监督当前前缀；因此阶段 A 不能作为在线机制的最终因果结论。下一阶段应转向 streaming delayed-evidence 任务，真正让约束逐步到达，并实现有限未提交窗口与 commit。
