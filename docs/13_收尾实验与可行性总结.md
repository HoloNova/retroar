# RetroAR 收尾实验与方向可行性总结

## 结论先行

**建议停止把当前 RetroAR 方案作为主要研究方向，保留代码、协议和实验记录，不继续追加训练或堆机制。**

理由不是“模型绝不能回头想”，也不是“负结果没有记录价值”，而是目前没有证据证明这套实现里的**提前生成、携带题目相关草稿、随后回改**比更简单的替代方法具有独特价值。在线优势和软信念机制的主张都还没有建立。

本次出现了明确的 soft 配置优势，必须如实保留，不能把它写成“所有 soft 都无效”；但低成本诊断发现，移除其题目相关的早期草稿几乎不影响成绩，故不能把高分直接归因于 RetroAR 的核心过程。

## 1. 完整性与预算

- `results/delayed_v1/status.json`：completed，20/20 次训练和20/20 次串行正式评估完成。
- 正式运行 4111.66 秒，约 **68.5 分钟**，未达到两小时上限。
- 四种方案、五个新训练种子（30–34）、每次5000步。源码/数据/配置及训练—评估元数据逐项一致，整题准确率与完整图约束满足率一致。
- 只用验证集选择模型，测试在全部训练结束后执行；没有据测试结果增加训练、换参数或延长预算。
- 41项回归测试通过；最终端到端冒烟 `delayed_smoke_v3` 完成。此前 v2 在等启动内存时被外层测试超时终止，已核对没有遗留训练进程并将状态更正为 blocked；正式任务不受该次短测影响。
- 本轮复用阶段B的1024/128/256题目划分。完整图在各划分之间无同构交集，但不是新的独立测试集。遮挡后，验证集5/128、测试集20/256的精确索引邻接观测在训练中出现过；不同完整图可以产生同一部分观测。数据审计见 `results/delayed_v1/data_audit.json`。

## 2. 实验到底测什么

早期隐藏所有自由点与颜色锚点之间的边，保留自由点间的连接；晚期一次性揭示所有边。所有目标标签只参与训练评分，不进入输入。

比较“线索齐了再生成”“丢弃旧草稿重新求解”“用hard草稿回改”“用soft草稿回改”。另给等待生成两次候选和约束筛选，以及对旧草稿做六种整体颜色置换的便宜对照。

这是**单次外部证据揭示、最后统一交卷**，不是完整在线流式模型，没有不可撤销前缀或中途输出。它已经偏离最初的“模型自己生成后文帮助前文”的设定，是收尾探针，不是原始想法的直接证明。

## 3. 预先安排的结果

整题正确率为五个种子平均，标准差是种子间波动，不是置信区间。

| 方案 | 整题正确率 | 种子间标准差 | 有效前向调用：早/晚 |
|---|---:|---:|---:|
| 等线索齐后生成 wait_ar | 74.45% | 3.12 pp | 0/6 |
| 等线索齐后生成两个候选 wait_k2 | 79.53% | 2.81 pp | 0/12 |
| 丢弃草稿，从空状态hard迭代 restart_hard | 66.64% | 6.33 pp | 0/6 |
| hard草稿回改 revise_hard | 80.16% | 2.18 pp | 6/6 |
| **soft草稿回改 revise_soft** | **90.23%** | **1.10 pp** | 6/6 |

重要配对差值：

- hard回改 − 等待一次生成：+5.70pp，5/5种子为正。
- hard回改 − 从空状态hard迭代：+13.52pp，5/5为正。
- **hard回改 − 等待两个候选：+0.63pp，只有2/5为正。**
- **soft回改 − hard回改：+10.08pp，5/5为正。**
- soft回改 − 等待两个候选：+10.70pp，5/5为正（描述性附加对比）。

协议以hard为主，要求它对restart_hard、wait_k2及自身颜色置换三个对照分别都≥3pp且5/5为正；**主要继续条件失败**。协议还预先规定，若soft出现≥3pp且5/5的反常信号，应保留为需独立重复的线索，而不是临时替换主要标准。本次正属于这种情况。

5个种子方向一致不等于已建立普遍或统计显著结论；双侧符号检验5/5的最小p为0.0625。本报告不挑选有利检验或将配对题目当作独立训练重复。

### 预算与耗时解释

训练参数、步数、每位置早晚各一次损失目标的数量和权重一致；生成与并行修订的依赖结构仍不同。

wait_ar / restart_hard与修订拥有相同晚期六次调用，却使用更少总计算。wait_k2与修订总调用相同，但需要更多证据到达后的计算。因此不能将“同一外部线索到达时间”说成“实际输出延迟完全相同”。

串行单题计时（各模型测32题后取中位数）的范围：wait_ar约3.9–5.0ms，restart_hard约3.7–4.4ms，hard回改约7.5–8.5ms，soft回改约6.9–8.3ms，wait_k2约8.7–9.8ms。这是小CPU模型的本机短测，不是大语言模型速度结论；回改时间包含早期计算，不等于晚期响应时间。

### 便宜对照与早期草稿质量

- 原封不动提交早期草稿仅约0.08%–0.70%整题正确。
- 枚举六种颜色置换后仅约2.42%–3.83%，无法解决大部分错误。
- 晚期一直不揭示线索仅约0.94%–4.84%；但这是完整证据训练下的推理分布变化，不能单独作为严格的因果信息价值估计。

这些结果意味着旧草稿不只是“颜色名字选错”，其结构也往往不正确。由于颜色标签在早期不可辨识，监督单个位置的真实颜色容易使soft边缘概率接近均匀，hard则被迫选一个答案。**每个位置的三个概率不等于保存了完整候选解之间的关联。**

## 4. soft高分是否真的需要旧草稿？（事后推理诊断）

没有追加训练。固定这五个已训练soft模型，只在第一轮晚期调用前替换草稿状态，之后继续原来的六轮soft求解，所有图条件、位置、present标记和模型参数不变。

早期实际草稿熵约1.087–1.092 nats，接近三分类上限ln3=1.099；平均最大概率约0.378–0.387。这次的早期soft确实非常不确定，但也因此几乎没有显著的题目相关状态。

| 第一轮晚期看到的草稿 | 最终整题正确率 |
|---|---:|
| 原始本题soft草稿 | 90.23% |
| **每个位置改成固定的1/3、1/3、1/3** | **90.39%** |
| 改成同批另一道题的草稿 | 89.92% |
| 所有自由点颜色向量设为零，present仍保留 | 90.63% |
| 本题soft草稿先取argmax变成one-hot | 86.80% |

原始分支逐种子精确复现正式评估，排除了分析脚本自身改变预测的明显错误。诊断输出：`results/delayed_v1/posthoc_state_probe.json`；复现脚本：`scripts/analyze_delayed_probe.py`。

**窄结论：这些已训练soft模型的最终性能，对本题早期草稿的细节几乎不敏感。**因此目前不能把90%的成绩归因于“提前想出了有用草稿，再根据新证据修正”。更符合观测的解释是：主要求解发生在完整线索到达后的soft迭代阶段。

若采用固定均匀初始化，推理时早期六次调用可直接省掉，因为除了草稿状态没有其他跨调用隐藏记忆。这里报告的是原脚本保留早期调用但覆盖其输出的诊断，没有把未测的加速作为实测结果。

边界：这是**在已训练模型上做的事后输入干预**，不是从零独立训练的restart_soft，也未独立重复；zeros保留present=True，并不等价于restart_hard起始的present=False。hardening只发生在揭示时一次，而非全程hard。不能用这些诊断给soft优势作唯一因果解释。缺少从头训练的restart_soft，正是当前方法论证的一个重要缺口。

## 5. 与此前全部结果放在一起

1. **首轮及阶段A：**允许草稿迭代修订有积极信号；但早期额外计算对照重复同样输入，不能作为有效预算强基线，监督也不完全一致。
2. **阶段B及新种子复现：**完整信息条件下，写完再改比边生成边改平均高约8.52pp（合并10种子，9/10为正）。不支持在线时机具有独特优势。
3. **草稿温度实验：**把状态压平确实改变了熵，却未达到继续标准，高温多半更差。只说明这套温度干预没有建立优势，不能推广为所有软信念都无效。
4. **本次延迟证据：**soft配置出现较大优势，必须修正“soft绝不是收益来源”这种过强说法；但用固定均匀状态替代旧草稿仍然达到同样成绩，未证明生成旧草稿及携带其信息是必要的。

共同指向：我们反复观察到了**完整条件下的迭代求解能力**，却还没有把它与最初的“生成过程中回改前文”这项主张清楚区分出来。

## 6. 可行性与是否放弃

### 工程可行性：可行，而且已经完成

小模型、概率草稿、回改、延迟揭示、检查点与有界调度都可以在本机CPU实现。问题不是写不出程序。

### 当前研究主张：证据不够

没有建立“在线优于写完再改”；本轮也没有证明“题目相关的早期草稿”比空白/均匀初始化更必要。soft配置差异是真信号，但其来源可能是晚期表示与优化方式，不能直接用来给RetroAR原始机制背书。

### 结论强度：不足以支撑一个独立的方法主张

已有文献已覆盖历史修订、可变后缀、连续/软状态和迭代细化等邻近方向。当前只有一个小型可精确求解任务族，缺少强soft重启对照、真正流式期限与跨任务验证，与前人工作的区分度不足。

可精确求解本身不使实验无效；它很适合验证机制。负结果本身也有记录价值。但要形成有普遍意义的结论，还需要回答更重要的问题、排除关键替代解释并补充跨任务证据。现有材料更适合作为研究记录/技术报告。

### 建议：停止这条实现主线，而不是宣判整个领域无效

- 不继续扩大模型、延长训练、增加温度或窗口搜索。
- 不为了用完预算而补实验；本轮训练已结束，没有启动新训练。
- 保留协议、实现、反常soft信号与全部原始结果，作为今后新问题的参考。
- 若将来重新打开，应先提出**真正的新研究问题**；例如只针对“soft从空白求解为何优于hard”做独立复现和完整基线。那是一个需要重新评估其与前人工作差异的分支，不应继续沿用“RetroAR已证明有效”的叙事。

**最终判断：这次探索值得做，也得到了清楚的止损依据。以尽量少耗时、早点得到可检验结论为目标，现在继续押注原方案的性价比偏低，建议收束。**
