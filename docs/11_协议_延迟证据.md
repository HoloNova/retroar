# 单次延迟证据：收尾验证协议

固定日期：2026-09-20。目标是低成本作继续/转向/停止的决策，不是寻找任何能让 RetroAR 获胜的任务。运行前固定此协议。上限不等于必须用满。

## 1. 纠正旧设计与结论

旧文档 `wait_fixed` 在早期已经锁死答案，只是晚交卷；不能代表真正的“等待后决定”。本协议取代旧文档的实验和继续标准。冗余前向也不是有效计算强基线。

此前温度实验只发现“用温度压平概率输入没有稳定改善这套模型”，不能证明所有软信念机制无效。高温会同时削弱输入的可区分程度，不等于得到更正确、更丰富的信念。soft 的小收益也不能仅据此归因于“延迟承诺”。这是一种可能解释，尚未被因果实验确认。

负结果记录不要求任务不能被经典算法求解；可精确评分的合成任务完全可以用于机制研究。真正短板是问题重要性、范围、强基线与可推广性，而不是存在精确求解器本身。

## 2. 任务与信息流

复用 `data/color6_stage_b.json` 固定划分（1024/128/256，六个自由点、三个固定颜色锚点），不扩大模型。完整图的同构划分沿用此前验证；这是旧任务的新信息时序和新训练种子，不是独立新测试集，也不声称新任务族复现。不同完整图可能共享相同部分图，必须在分析中说明。

早期只给自由点之间的边，所有自由点与锚点之间的边双向隐藏。颜色锚点本身和锚点之间的边可见。遮挡由邻接位置决定，不读取目标标签。隐藏锚点联系后，早期至少存在整体颜色置换歧义；晚期一次性公开所有边，不直接给答案。

每个方案训练时先基于部分图自回归生成六个位置，再进行六次晚期计算。所有方案共有早期六个 CE 损失与晚期六个 CE 损失，晚期第 t 次只监督第 t 个位置；总计每个位置两次，权重一致。状态反馈全部 detach，不跨草稿反传。早期损失可能存在不可消除歧义，这是所有模型相同的辅助训练任务，不把低早期准确率解释为不会学习。

这不是完整流式任务：没有冻结前缀、连续证据到达或中途输出要求。答案统一在晚期六次调用结束后提交。它只能筛查“旧草稿是否比到时再想更有用”。

## 3. 对照和预算

| 模式 | 晚期怎么做 | 有效推理调用（早/晚） |
|---|---|---|
| wait_ar | 不读旧草稿，线索齐后自回归生成 | 0/6 |
| restart_hard | 不读旧草稿，从空状态开始六轮并行求解 | 0/6 |
| revise_hard | 读取早期 hard 草稿，六轮整段回改 | 6/6 |
| revise_soft | 同上，soft T=1；不再搜索温度 | 6/6 |
| wait_k2（wait_ar 推理对照） | 贪心候选+一个随机候选，用完整图冲突数筛选 | 0/12 |
| permutation_repair（每模型诊断） | 枚举旧草稿的六种整体颜色置换，选冲突最少者 | 6/0 + 六次廉价评分 |
| frozen_early | 直接提交旧草稿 | 6/0 |
| no_reveal | 晚期也只见部分图 | 相应流程相同 |

训练时 waiting/restart 也完成早期辅助任务以匹配训练预算，但推理时不必运行这些丢弃的计算。计时必须跳过，不能再用“多算但丢掉”冒充有效推理预算。

三种公平关系分别报告，不能混为一谈：
- wait_ar / restart_hard 与修订有相同晚期六调用，但更少总调用；
- wait_k2 总调用相同，但需要十二次晚期调用（等待后计算延迟更长）；
- 所有方案是相同“外部证据揭示时间”，不因此声称相同真实墙钟输出延迟。

前向调用相同不意味着 FLOPs 或监督路径完全相同。参数规模、训练步数、损失目标计数相同；AR 的串行依赖与修订的并行输出不同，这是待比较机制的一部分。记录单题串行实测耗时，不只数调用。规则评分只用观测到的完整图，不读答案；no_reveal 不允许完整图打分辅助选答案。

## 4. 规模、运行与停止

四种训练方案 × 新种子 30–34 = 20 次；每次 5000 步，batch16，单线程，两进程训练。与阶段 B 保持模型和每次训练步数相同。只用验证集选择最佳模型（并列保留较早者），全部训练结束后串行正式测试。

不做温度、窗口、网络宽度、数据难度搜索。先做 100 步小数据端到端冒烟测试，只用于程序验证和速度估算，不以测试分数改变设计。正式 suite 单次执行两小时硬上限、单模型30分钟。RSS上限1GiB/worker，系统可用低于768MiB停止，只管理自己的子进程。首个子进程启动须可用内存≥1152MiB（为实测约300MiB进程保留余量），并发第二个须≥1536MiB；不足以并行则单任务运行，不降低768MiB停止线。外部SIGTERM会中止自己的子进程并写blocked。超时或保护停止写 blocked，不伪装完成，不自动延长或重启。检查点支持显式恢复且严格比对源代码/数据/配置。

状态：`results/delayed_v1/status.json`；逐运行状态与检查点在各子目录；汇总 `summary.json`、`report.md`。正式命令：

```bash
.venv/bin/python -m retroar_min.delayed --config configs/cpu_delayed.json --output results/delayed_v1
```

## 5. 事前决策规则（工程止损规则，不是假设检验显著性）

主要比较以 hard 为主，避免选择性挑 soft/温度：

1. 若 revise_hard 比 **restart_hard、wait_k2 以及自身 permutation_repair 三者分别都高至少3pp，且每项5/5种子为正**，才建议考虑下一阶段；同时报告与 wait_ar 的差值、晚期调用和实测时间，不能直接称突破或成功。
2. 只胜 wait_ar、不胜更强对照，或只胜 frozen_early：不支持独特机制；不自动增加计算继续追分。
3. revise_soft 与 revise_hard 比较是次要结果；软版偶然胜出不替代主要条件。如 soft ≥3pp且5/5为正，只记为需独立重复的反常信号，不事后改变本轮主要标准。
4. 等待/restart 最佳验证和测试都太差（例如最佳方案测试<50%）、训练仍明显欠拟合、或遮挡/信息隔离检查失败：判为本轮不充分，不能否定机制；在本轮资源上限内不自动增加训练。
5. 如果上述继续条件不满足且实现通过检查，建议停止把当前方案作为主要研究方向。保留负面结果记录即可；是否值得继续投入要看跨任务证据和与前人工作的差异，而不是“有负结果就能继续”。

最终综合三轮已有结果与这次探针，区分：软件可实现、当前机制是否有独特收益、是否有与前人工作相区分的余地、是否值得追加资源。不把单个六点图任务的失败说成普遍不可能。
